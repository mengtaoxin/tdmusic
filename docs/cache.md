# Audio cache and covers

Catalog load/enrich: [catalog.md](catalog.md). Prefetch / play download path: [playback.md](playback.md).

## Audio cache (SQLite Wasm + OPFS)

- Access goes through `lib/cache/cacheStore` (and `playHistoryStore` for listen history) on the shared app SQLite database (`lib/storage/appDb`). Do not open OPFS or SQLite from views. Unit tests use an in-memory SQLite DB. `fake-indexeddb` remains for tdkit dual-stack logs.

- Playable paths (`http(s)://` and site-absolute `/…`) are downloaded into the local SQLite DB on play. Downloads use `fetch(…, { cache: 'no-cache' })` so the browser revalidates with the origin (avoids re-storing a stale HTTP disk-cache copy after Settings clears the local cache).
- When SQLite/OPFS cannot be used (private/incognito mode, missing OPFS, missing cross-origin isolation / COOP+COEP, open/write failures, quota), `resolvePlayableUrl` falls back to the original source path so `<audio>` streams directly without caching. The session remembers that the music cache is unavailable (`musicCacheAvailability`) and skips further cache attempts; network download failures (`downloadFailed:…`) still reject and skip the track. Prefetch / manual downloads keep failing in that mode (best-effort / logged).
- Audio downloads (play, prefetch, and manual) go through `ensureTrackCached` and share a global limiter (`downloadLimiter`): at most **3** music-file fetches run at once. Priorities: play-path downloads `high` (via `resolvePlayableUrl`) > prefetch `normal` > manual downloads `low`.
  - Preemption: creating (or raising) a job aborts every **running** job of lower priority (`AbortSignal` passed to `fetch`). The aborted job drops its partial download, goes back to the waiting list ahead of same-priority jobs queued after it, and restarts **from scratch** later (no HTTP Range resume).
  - A job starts only when a slot is free and no higher-priority job is running or waiting, even if slots are idle. Same priority runs FIFO.
  - Same-URL in-flight work is shared and counts as one slot; a request at a higher priority raises the shared job (e.g. playing a track that is being manually downloaded makes it `high`, so prefetch cannot abort it). In-flight prefetch is not aborted when the user skips.
- Manual downloads: the track actions menu (“Download”) and “Download all” on multi-track pages (Songs, album, artist, artist album, playlist) call `enqueueManualDownloads`. The queue (`download_queue`) persists in SQLite, skips non-playable / cached / already queued tracks, feeds at most 3 tracks at a time into `ensureTrackCached(…, { priority: 'low' })`, and deletes each row after success or failure (failures are logged in English). On startup `bindAppManualDownloads` (`src/stores/bindAppCatalog.ts`) calls `resumeManualDownloads`, so rows left by a closed page continue. Each success re-enqueues enrichment (`scheduleEnrichTrack`).
- After the current track’s playable URL is bound and `loadedmetadata` fires (playback can start), up to the next **3** upcoming queue tracks are also prefetched into SQLite (`prefetchUpcoming` / `upcomingQueueIds`): linear forward through the play queue (wraps when repeat **all**); none when repeat **one**. Shuffle reorders the queue itself, so prefetch stays linear. Best-effort; failures are ignored. Queue chunk appends re-trigger prefetch so early `playFrom` heads still fill the window (those jobs stay `normal`, so they wait if a play download is still high-priority). After each successful prefetch cache, that track is re-enqueued for enrichment (`scheduleEnrichTrack`) so list cover art updates when ID3/cover becomes available from the cached blob.
- Prefetch keeps running while `document.hidden`, so the next tracks are already cached when playback continues in the background. Hiding the page does not abort prefetch downloads. When the page becomes visible again and playback is still running, prefetch runs again.
- Tables (shared DB file `/tdmusic.sqlite3` in OPFS): `track_meta` (download status), `files` (audio + cover blobs), `track_extracted` (extracted title/artist/album text only), `download_queue` (unfinished manual downloads `{ sourceUrl, id, addedAt }`, oldest first), plus `play_history` (see [playback.md](playback.md)).
- `track_meta.status`: `pending` while downloading, `ready` when playable. Only `ready` counts as cached; failed downloads remove partial records and may be retried.
- In-flight ingest publishes progress through `cacheDownloadState` (by source URL / track id) so covers can animate; `done` (success or failure) and cache-clear cancel the marker.
- When a download finally fails (not a preemption restart), `cacheDownloadState` keeps the reason in memory (`getTrackDownloadFailure`: error message, HTTP status when the server answered non-OK, time). The next download attempt or a cache clear forgets it; it does not survive a page reload.
- Track actions menu → “Track info” opens `TrackInfoDialog`: display fields with their source (config / audio tags / file name), cover source and size, download status (with the failure reason above), cache time and file size (`getTrackCacheDetails`), track id, path, volume ratio, and 30-day play count / last played (`getTrackPlayStats`).
- Audio blob key: `__audio__`. Cover art blob key: `__cover__` (not stored as data URLs in `trackMeta`).
- Playable `blob:` URLs from `getCachedBlobUrl` normalize MIME from the source path extension at read time (e.g. `.flac` → `audio/flac`) when the stored type differs; SQLite bytes and stored mime are not rewritten. Cover object URLs are unchanged.
- After a new playable URL is assigned to `<audio>`, `releaseAudioBlobUrlsExcept` revokes every other audio object URL. The current `audio.src` is kept until the next successful bind. Cover object URLs stay for list and now-playing images. Playing the same track again creates a fresh audio object URL from SQLite.
- Before writing large blobs, soft quota check via `navigator.storage.estimate()`: if `usage + size > quota * 0.85`, evict oldest `ready` tracks by `downloadedAt` until under the limit (no-op when quota unknown).
- Settings → “Clear all cache” asks for confirmation, then `clearMusicCachesAndRefresh` drops the catalog enrich queue, clears audio/cover blobs + extracted metadata + the manual download queue (`musicCache.clearAllMusicCaches` does not know about enrich), clears listen history (`playHistory.clearPlayHistory`), clears now playing and the play queue (`player.clearNowPlaying`, including `tdmusic.player`), resets in-memory display fields to config-only, and re-enqueues enrichment. The same section shows the current size of cached audio and cover blobs (`getMusicCacheSizeBytes`); that figure refreshes after a successful clear.
- No migration from legacy Dexie IndexedDB caches; existing `music-cache` / `play-history` data is left behind. tdkit settings/logs may still use IndexedDB until that package migrates (dual-stack).
- Public cache API for app code: `lib/cache/musicCache` (including `putCoverFile`, `getMusicCacheSizeBytes`, and cache-availability helpers used by play resolution). `trackMetadata` / `cacheStore` / `cacheIngest` / `cacheEviction` / `downloadLimiter` / `downloadQueue` / `musicCacheAvailability` are internal to the cache stack. Cache must not import catalog.

## Cover images

- Extracted covers are stored as BLOBs in SQLite (`files` / `__cover__`) and surfaced to the UI as `blob:` object URLs.
- All cover art goes through `CoverImg`, which loads the image only after the element enters the viewport (`IntersectionObserver`). Pass `eager` only when the image must load immediately.
- While the **current** track’s audio is downloading into the local cache, `CoverImg` replaces the still cover (or the music-note placeholder) with a simple circular loading indicator. When ingest finishes (`track_meta.status` `ready`), the real cover is shown (config URL or extracted `__cover__` blob). Prefetch downloads do not animate other rows.
- Songs, Artists, Albums, and artist album galleries virtualize with `@tanstack/react-virtual` (host sizing via `useVirtualListHost`), so off-screen rows (and album covers) are not mounted. Album galleries (`AlbumGallery`) chunk tiles into responsive rows first, then virtualize those rows.
